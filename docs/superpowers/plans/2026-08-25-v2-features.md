# V2 Features Implementation Plan (manual credentials, scheduling, finishers)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v1 "v2" placeholders with working features: manual-entry credential profiles (auto-login at run start), scheduled runs (executed while the app is open), suite JSON import, Projects sort, honored retry count, and a real Reports screen.

**Architecture:** Engine gains pure capabilities (manual login + retries in the runner, schedules CRUD in the store, a `computeNextRunAt` helper); main gains a 60-second scheduler loop and a shared `executeRun()` helper both IPC and the scheduler call; renderer activates the existing placeholder UI (Credential modal Manual Entry tab, Run modal Schedule tab, Dashboard Scheduled Runs card) and adds Import/Sort/Reports. Secrets follow the v1 pattern exactly: manual passwords are an opaque encrypted blob via the existing `saveCredential(meta, blob)` mechanism — encrypted by main with safeStorage, never sent to the renderer.

**Tech Stack:** existing v1 stack only — no new dependencies.

**Spec:** approved scope in chat 2026-08-25 (user selected: manual-entry credentials / scheduled runs / small finishers; Jira push and Repo Connection excluded). This plan is the design of record.

## Global Constraints

- Branch `feature/v2-features` off `main`. Plain JS; engine CommonJS, never `require('electron')`.
- Secrets: passwords exist only inside main-process memory and safeStorage-encrypted blobs on disk. Never in IPC responses, reports, exports, logs, or the recorder (`type=password` inputs already record `********` — keep it that way). A run report must never contain the password (manual login happens BEFORE steps and is not a report step; the report gets a boolean `manualLogin: true`).
- Store interface additions (`listSchedules`, `saveSchedule`, `deleteSchedule`) mirror the existing entity patterns in `src/engine/store.js` so the future cloud store can mirror them 1:1.
- Verification floor per task: `npm test` green and `npm run smoke` prints `SMOKE OK` exit 0.
- Renderer conventions: shadcn primitives from `src/renderer/src/components/ui/`, `useToast()`, no native dialogs, all data via `window.qaflow`.
- Commits: conventional messages, NO Claude/Co-Authored-By attribution lines, one commit per task.

### Task 1: Engine — manual login, retries, schedules CRUD, next-run math

**Files:**
- Modify: `src/engine/runner.js` (options `manualLogin`, `retries`), `src/engine/store.js` (schedules CRUD)
- Create: `src/engine/schedule.js` (`computeNextRunAt`), `test/fixtures/site/login.html`
- Test: `test/runner.test.js` (additions), `test/store.test.js` (additions), `test/schedule.test.js`

**Interfaces:**
- Consumes: existing `runSuite(suite, opts)` and `createStore(baseDir)` (read both before editing).
- Produces:
  - `runSuite(suite, { ..., manualLogin?: { loginUrl, username, password }, retries?: number })`. Manual login runs before step 1: `page.goto(loginUrl)`, fill the first visible `input[type="email"], input[type="text"]` with username, first `input[type="password"]` with password, click `button[type="submit"], input[type="submit"]` (fallback: press Enter in the password field), `waitForLoadState('networkidle')` with the step timeout. Login failure (selector not found / navigation error) fails the run with a clear error `Manual login failed: <reason>` and NO password text in the message. Report gains `manualLogin: true` when used and `attempts: <n>` always (1 when no retry).
  - `retries`: when the attempt's status is `failed` and attempts ≤ retries, discard that attempt's report and re-run the whole suite (fresh browser); keep the final attempt's report with `attempts` set. `retries` defaults 0.
  - Store: `listSchedules()` (sorted by `nextRunAt` asc), `saveSchedule(schedule)` (upsert by id, stamps `updatedAt`; new ids `sched-<uuid>` allowed from caller), `deleteSchedule(id)`; persisted in `schedules.json` beside the other JSON files. Schedule shape:
    `{ id, suiteId, projectId, name, environment, headless: true, credentialProfileId: null, at, recurrence: 'once'|'daily'|'weekly', enabled: true, lastRunAt: null, nextRunAt, createdAt, updatedAt }`.
  - `computeNextRunAt(schedule, fromIso)` in `schedule.js`: `'once'` → `schedule.at` if still in the future else `null`; `'daily'`/`'weekly'` → the first occurrence of `at`'s time-of-day (and weekday, for weekly) strictly after `fromIso`. Pure function, ISO strings in/out.

Extend the fixture server if needed (read `test/fixtures/serve.js`). Write failing tests: (a) runner test — suite of one `assertVisible` on a dashboard element, `manualLogin` with correct creds → run passes, report has `manualLogin: true`, `attempts: 1`, and `JSON.stringify(report)` does NOT contain the password; (b) wrong password → run fails with `Manual login failed` or a failed assert — assert the report never contains `secret123`; (c) retry test — suite asserting an element that never exists, `retries: 1` → final report `attempts: 2`, status failed; (d) store schedules CRUD round-trip + sort; (e) `test/schedule.test.js` table-driven cases for once/daily/weekly incl. the once-in-the-past → null case. Run: all new tests fail.

### Task 2: Main — scheduler service, shared executeRun, manual-credential blobs, suite import IPC

**Files:**
- Create: `src/main/scheduler.js`
- Modify: `src/main/ipc.js`, `src/main/preload.js`
- Test: engine suite stays green; scheduler logic is factored so its pure parts live in `schedule.js` (already tested); manual smoke.

**Interfaces:**
- Consumes: Task 1 signatures verbatim.
- Produces:
  - ipc.js refactor: extract the body of `runs:run` into `async function executeRun(suiteId, { environment, headless, credentialProfileId }, triggeredBy)` used by both the IPC handler (`'manual'`) and the scheduler (`'schedule'`). Inside it, credential handling branches on the profile's `mode`: `'session'` (default, existing storageState temp-file path) or `'manual'` → decrypt blob, `JSON.parse` to `{ username, password }`, pass `manualLogin: { loginUrl: profile.loginUrl, username, password }` to `runSuite`, zero the variable after. `runs:run` also now forwards a `retries` option into `runSuite`.
  - `session:saveManual` IPC: args `{ name, projectId, environment, loginUrl, username, password }` → encrypt `JSON.stringify({username,password})` with safeStorage (plaintext+`encrypted:false` fallback exactly like the existing capture path), `store.saveCredential({ ...meta, mode: 'manual' }, blob)`. Existing capture path saves `mode: 'session'`. The password never returns to the renderer.
  - `suites:importFromFile` IPC: `dialog.showOpenDialog` (JSON filter) → read file → validate (`name` string and `steps` array whose entries have a known `type`) → assign fresh id, `store.saveSuite` → return the saved suite; invalid file → throw `Error('Not a valid suite JSON file')`.
  - `scheduler.js`: `createScheduler({ store, executeRun, notify })` → `{ start(), stop(), checkNow() }`. `start()` = 60s interval calling `checkNow()`. `checkNow()`: for each enabled schedule with `nextRunAt <= now`: run `executeRun(s.suiteId, {environment: s.environment, headless: true, credentialProfileId: s.credentialProfileId}, 'schedule')` (await sequentially; wrap per-schedule try/catch), then set `lastRunAt`, recompute `nextRunAt` via `computeNextRunAt` (recurrence `'once'` → `enabled: false, nextRunAt: null`), save, and `notify(schedule, status)` → main forwards a `schedules:fired` push event to the renderer. Wire `createScheduler(...).start()` in main.js after boot (guard with try/catch; smoke unaffected).
  - preload additions: `schedules.{list,save,remove}` (`schedules:list|save|remove` handlers → store CRUD), `session.saveManual`, `suites.importFromFile`; allowlist push event `schedules:fired`. Run report shape addition `triggeredBy: 'schedule'` is a legal value everywhere it renders.

- [ ] Step 1: implement per Interfaces; run `npm test` (green — no engine regressions) and `npm run smoke`.
- [ ] Step 2: Commit `feat: scheduler loop, shared executeRun, manual credential blobs, suite import ipc`.
