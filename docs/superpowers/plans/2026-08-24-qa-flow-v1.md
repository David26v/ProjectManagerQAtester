# QA Flow v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build QA Flow — an Electron + Playwright desktop app where a non-technical QA tester records a browser flow once, replays it as an automated test with video/screenshot/console/network capture, reviews evidence, and exports a structured bug report (JSON / Excel / Jira-style ticket / zip "Send to David" bundle), with a local REST API + CLI for automation.

**Architecture:** Clean split — `src/engine/` is pure Node (no Electron imports): storage, Playwright runner, recorder, session capture, exporters, REST API. `src/main/` is the Electron shell that wires the engine to `app.getPath('userData')` and exposes it to the renderer via a `preload.js` contextBridge. `src/renderer/` is a vanilla-JS (no bundler) single-window UI with a left sidebar and screen modules, matching the PNG mockups pixel-close.

**Tech Stack:** Electron (latest stable), `playwright` (not @playwright/test — we drive the library directly), `exceljs`, `archiver`, `express`, Node `node:test` for engine tests. Plain JavaScript everywhere (CommonJS in engine/main, ES modules in renderer). No TypeScript, no bundler, no React.

## Global Constraints

- Repo root: `D:\personal-project\CritalCaller\qa-flow`. Plain JavaScript only. `src/engine/**` and `src/main/**` are CommonJS (`require`); `src/renderer/**` uses `<script type="module">` ES modules. No bundler, no TS, no React.
- `src/engine/**` must never `require('electron')` — it receives paths/config as parameters. Engine must be unit-testable with plain `node --test`.
- Secrets never appear in reports, exports, or the renderer: credential profiles are encrypted with Electron `safeStorage` in the main process only; report JSON contains no cookies/tokens/passwords.
- REST API binds to `127.0.0.1` only.
- Report JSON shape is FIXED (spec section 5): `{ suiteName, targetUrl, startedAt, finishedAt, status: "passed"|"failed", steps: [{ name, status, error?, screenshot? }], consoleErrors: [{ text }], networkFailures: [{ url, failure }], videoPath }` — extended with `runId`, `suiteId`, `projectId`, `environment`, `capturedMedia`, `reportSelection` (section 21).
- UI: light theme matching mockups — sidebar 230px white, main bg `#f6f8fb`, primary blue `#2563eb`, green `#16a34a` pass, red `#dc2626` fail, radius 10–12px cards, system font stack `Inter, "Segoe UI", system-ui, sans-serif`. App title bar text "QA Flow", sidebar footer shows "Electron v<version> / All systems operational".
- Data lives under a single base dir (`userData/qaflow-data` in the app; a temp dir in tests): `projects.json`, `suites/<suiteId>.json`, `runs/<runId>/report.json` + media, `credentials/index.json` + `credentials/<profileId>.bin`, `tickets.json`, `settings.json`.
- Commits: conventional messages (`feat: …`, `test: …`), NO Claude/Co-Authored-By attribution lines, commit after each task.
- Verification floor for every task: `npm test` passes and (from Task 6 on) `npx electron . --smoke` exits 0.

## Shared Data Model (all tasks)

```js
// Project
{ id, name, key, baseUrl, type: "web",            // type fixed "web" in v1
  environments: [{ name, baseUrl }],               // e.g. Staging/Production
  defaultEnvironment, description, createdAt, updatedAt, primary: false }

// Suite (recorded flow)
{ id, projectId, name, description, tags: [],      // e.g. ["smoke","full"]
  environment,                                     // default env name
  steps: [ Step ], createdAt, updatedAt, archived: false }

// Step — the ONLY step vocabulary in v1 (recorder emits these, runner executes these)
{ type: "goto"|"click"|"fill"|"press"|"select"|"waitFor"|"assertVisible"|"assertText",
  name,               // human label e.g. 'Click "Sign in"'
  selector,           // omitted for goto/press
  value,              // url for goto, text for fill, key for press, option for select, expected text for assertText
  timeout: 10000 }

// Run (created by runner; persisted at runs/<runId>/report.json)
{ runId, suiteId, projectId, suiteName, targetUrl, environment,
  startedAt, finishedAt, status: "passed"|"failed",
  triggeredBy: "manual"|"api"|"cli",
  steps: [{ name, status: "passed"|"failed"|"skipped", error?, screenshot?, durationMs }],
  consoleErrors: [{ text }], networkFailures: [{ url, failure }],
  videoPath,                                        // relative to run dir
  capturedMedia: [{ id, type: "video"|"screenshot", path, stepIndex? }],
  reportSelection: { selectedMediaIds: [], notes: {} } | null }

// CredentialProfile (index.json holds metadata; .bin holds safeStorage-encrypted storageState JSON)
{ id, name, projectId, environment, loginUrl, username, createdAt, lastUsedAt }
// NOTE: password is never persisted; only the captured Playwright storageState is, encrypted.

// Ticket (kanban)
{ id: "BUG-<n>", title, description, severity: "critical"|"high"|"medium"|"low",
  status: "backlog"|"ready"|"in_progress"|"blocked"|"done",
  projectId, runId?, labels: [], assignee, reporter,
  reproductionSteps: [], attachments: [{ mediaId, path, type }],
  comments: [{ author, text, at }], createdAt, updatedAt }
```

**Files:**

**Interfaces:**
- Consumes: `createStore(baseDir)` from Task 1.
- Produces: `async runSuite({ store, suite, project, environment, storageStatePath = null, headless = true, onProgress = null })` → the persisted Run report object (shape in Shared Data Model). `onProgress(evt)` receives `{ type: "step-start"|"step-end", index, name, status?, error? }`.

Runner behavior (this is the heart of the product — implement exactly):
- Resolve `targetUrl` = environment's `baseUrl` (fall back to `project.baseUrl`). Relative `goto` values (`/login`) resolve against it; absolute URLs pass through.
- `chromium.launch({ headless })`; `browser.newContext({ recordVideo: { dir: runDir }, storageState: storageStatePath || undefined, viewport: { width: 1280, height: 800 } })`.
- Collect `page.on('console', msg => msg.type() === 'error' && consoleErrors.push({ text: msg.text() }))`; `page.on('requestfailed', r => networkFailures.push({ url: r.url(), failure: r.failure()?.errorText }))`; also push responses with `status() >= 400` as `{ text: "<status> <statusText> - <url>" }` into consoleErrors (matches spec example `403 Forbidden - /api/...`).
- Execute steps sequentially: `goto`→`page.goto`, `click`→`page.click`, `fill`→`page.fill`, `press`→`page.keyboard.press(value)`, `select`→`page.selectOption`, `waitFor`→`page.waitForSelector`, `assertVisible`→`page.waitForSelector(sel,{state:'visible'})`, `assertText`→ wait for selector then compare `textContent` contains `value` (mismatch throws `Expected "<value>" but found "<actual>"`). Each step gets `durationMs`.
- On step failure: capture `page.screenshot` to `runDir/<slug(step.name)>-<Date.now()>.png`, record `error: e.message`, mark step failed, mark all later steps `skipped`, run status `failed`.
- Always: close context (finalizes video), rename video file to `video.webm` in runDir, set `videoPath: "video.webm"`, build `capturedMedia` (video + every screenshot), `reportSelection: null`, save via `store.saveRun`, close browser in `finally`.
- `runId` = `run-<Date.now()>-<4 random hex>`.

**Files:**

- Test: `test/recorder.test.js`

**Interfaces:**
- Consumes: fixture server from Task 2.
- Produces:
  `createRecorder()` → `{ async start({ url, storageStatePath = null, onStep = null }), async stop() → steps[], isRunning() }`. `start` launches headed Chromium, navigates to `url`, records user actions as Step objects (Shared Data Model vocabulary). `stop()` closes the browser and returns collected steps (first step is always `{ type:'goto', value: url, name: 'Navigate to <url>' }`). If the user closes the browser window, recorder resolves as stopped.
  `async captureSession({ loginUrl })` → launches headed Chromium at `loginUrl`, waits until the user closes the window (or `finish()` called), then returns `storageStateJson` string via `context.storageState()`. Export shape: `{ start({loginUrl}) → { finished: Promise<string> , async finish(), async cancel() } }`.

Recorder mechanics (implement this way):
- `recorder-inject.js` exports a single self-contained function-body string (or a function serialized with `.toString()`) injected via `context.addInitScript`. It listens in capture phase for `click`, `input` (debounced per element — emit one `fill` with final value on blur/enter), `change` on `<select>`, and `keydown` Enter. For each event it computes a selector with priority: `[data-testid]` → `#id` → `[name]` → `a:has-text()/button text` fallback `tag.class:nth-of-type` — then calls `window.__qaflowRecord({type, selector, value, name, tagName})`.
- `recorder.js`: `context.exposeBinding('__qaflowRecord', handler)` pushes normalized Steps; `page.on('framenavigated')` on the main frame appends a `goto` step only when navigation was user-initiated (URL differs from last recorded goto and last event was not a click within 2s — keep simple: record it as `{type:'waitFor'... }`? NO — keep simpler rule: append goto only if no step recorded in the last 2s). Password fields (`input[type=password]`) record value `"********"` literally; the step name says `Input password`.
- Steps get names: goto `Navigate to <url>`, click `Click <text-or-selector>`, fill `Input <selector>`, select `Select <value>`, press `Press <key>`.
